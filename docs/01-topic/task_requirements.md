# 任务要求（最低完成要求 + 拓展目标）

> 来源：《成都理工大学本科毕业论文题目与任务要求总结》物联网工程专业部分（导师曾维），原文照录 + 拆解。本文件为题目冻结区内容。

## 一、最低完成要求（原文）

> 至少搭建2—3个传感/控制节点；实现FreeRTOS多任务采集与通信；建立节点状态和故障监测机制；人为注入通信中断、传感器异常或节点失联等至少2类故障；评价故障检测时间、误报/漏报或故障恢复时间；测试通信延迟、丢包率和任务响应。

### 统一写法拆解（必须做什么 / 与谁比较 / 测哪些指标 / 完成哪类分析）

| # | 要求 | 论文对应位置（定稿前逐条核对） |
|---|---|---|
| 1 | 搭建 2—3 个传感/控制节点 | 第3章 系统总体设计 / 第4章 系统实现 |
| 2 | FreeRTOS 多任务采集与通信（任务划分、优先级、队列/信号量） | 第3章 任务设计 + 第4章实现说明 |
| 3 | 节点状态和故障监测机制（三类判据 + 阈值取法及依据） | 第3章 判据设计（专业深度核心） |
| 4 | 注入 ≥2 类故障（通信中断 / 传感器异常 / 节点失联），每类 ≥10 次 | 第5章 故障注入实验 |
| 5 | 故障检测时间（均值、最大值）、误报率、漏报率 | 第5章 结果表 |
| 6 | 通信延迟、丢包率、任务响应时间 | 第5章 性能测试表 |
| 7 | 完整系统 + 通信链路 + 数据管理 | 第3、4章 |
| 8 | 定量性能实验 + 异常工况测试 | 第5章（无第5章即不达标） |

**禁止用语**（任务书/论文）：基本完成、跑通模型、完成基本功能、能够识别、系统能运行。

## 二、拓展目标（原文）

- CAN/RS485 等总线
- 节点自动恢复
- 更多故障类型
- 调度性能分析

## 三、导师技术方案中的强制细节

1. **三类判据**：心跳超时（节点失联）、数据合理性检查（超量程、长时间不变、跳变超阈值 → 传感器故障）、通信质量统计（连续丢包率超限 → 通信故障）。**每类判据写清阈值取法及依据**。
2. **故障注入记录方法**：故障注入的时间点与判据触发时刻如何记录，方法要写清楚（建议：上位机统一毫秒时间戳日志，注入动作打标记，检测时间 = 触发时刻 − 注入时刻）。
3. **每类故障重复注入不少于 10 次**，统计检测时间均值与最大值、误报率、漏报率。
4. **硬件风险**：多节点硬件翻倍，建议备份一套节点硬件；论文中必须区分"接触不良导致的偶发数据丢失"与"注入的故障"，否则误报率数据不可信。
5. **开题材料**须含数据/语料来源与合规说明（本课题为自采传感器数据，说明数据由本人实验采集、不含个人信息即可）。
6. **开题后 4 周**交第一版 Baseline 结果表或系统架构设计（中期前硬节点）。
7. **文献**：导师给的 20 条为建议骨架，须逐条数据库核实、补全著录；未读过的不得列入。

## 四、组内通用硬性要求（物联网/嵌入式系统类）

必须包含：完整系统、通信链路、数据管理、一个核心专业机制、定量性能实验、异常工况测试。
仅证明"采集成功、上传成功、页面显示成功"**不足以**作为本科毕设最低要求。
