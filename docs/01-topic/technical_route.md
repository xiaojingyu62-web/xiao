# 技术路线（题目冻结区）

> 依据：导师《技术方案与参考文献建议》肖竞宇部分（Page 43–45）+ 本人硬件现状（2026-09-30：暂无硬件，先定方案再采购）。

## 1. 系统组成

```
┌─────────────────┐   ┌─────────────────┐   ┌─────────────────┐
│  采集节点 Node1  │   │  采集节点 Node2  │   │  采集节点 Node3  │
│  STM32+FreeRTOS │   │  STM32+FreeRTOS │   │  STM32+FreeRTOS │
│  传感器×2~3      │   │  传感器×2~3      │   │  传感器×2~3      │
│  MAX485 收发器   │   │  MAX485 收发器   │   │  MAX485 收发器   │
└────────┬────────┘   └────────┬────────┘   └────────┬────────┘
         └──────────────┬──────┴──────────────┬──────┘
                  RS485 差分总线（A/B/ GND，主从轮询）
                        │
                 ┌──────┴──────┐
                 │  汇聚节点/网关 │  ←— 或 PC 直接作主机（USB-RS485）
                 └──────┬──────┘
                        │ USB 串口
                 ┌──────┴──────┐
                 │   上位机      │  数据管理(存储/展示) + 故障注入标记
                 └─────────────┘
```

- **采集节点 2~3 个**：每节点 1 块 STM32 + 2~3 个传感器 + MAX485 模块。
- **汇聚节点**：初期可用 PC + USB-RS485 适配器直接作总线主机（最简、时间戳最准）；后续可加 1 块 STM32 作独立汇聚节点以满足"汇聚节点或网关"的完整系统要求。
- **上位机**：PC 端程序（建议 Python + pyserial + SQLite/CSV），承担数据管理、故障注入时间标记、检测时间统计。
- **FreeRTOS 任务划分**（每节点）：采集任务（周期触发）、通信任务（总线收发，队列同步）、自检任务（本地判据预处理/心跳发送）。

## 2. 通信方案选择（采购前必须定）

| 方案 | 优点 | 缺点 | 与同组边界 |
|---|---|---|---|
| **串口+RS485（推荐）** | 时延确定、丢包率统计干净；拔 A/B 线即可注入"通信中断"，故障注入可控可重复；不依赖无线环境，误报率不受 WiFi 干扰污染；主从轮询天然产生"请求-响应"配对帧，丢包/时延易测量 | 需布线；上位机需 USB-RS485 适配器 | 周品（ESP32+MQTT/WiFi 断网补传）、李钦颖（STM32+ESP8266+MQTT）都走无线，我走有线总线，边界清晰不撞车 |
| ESP-NOW/WiFi | 免布线、无线干扰可作为额外故障源 | 无线干扰导致的偶发丢包与注入故障难区分，误报率难归因；需每节点加无线模块 | 与周品/李钦颖路线重叠 |
| CAN | 差分总线、工业级 | 节点成本与资料门槛高，作为拓展目标更合适 | — |

**结论：第一阶段采用串口 + RS485 主从轮询**（导师原话"按现有硬件定"，现无硬件，按实验可控性定）；CAN 作为拓展目标在时间允许时增加一组对比实验。

## 3. 核心专业机制：三类判据（每类含阈值取法及依据）

| 判据 | 对应故障 | 初始阈值（待预实验整定） | 取法与依据 |
|---|---|---|---|
| ① 心跳超时 | 节点失联（断电/死机） | 正常 1s 一发，连续 **3s** 未收到判失联 | 正常抖动 <1 个发送周期，取 3 倍周期容忍偶发误帧；依据为主从轮询周期实测最大抖动（预实验标定） |
| ② 数据合理性检查 | 传感器故障（脱落/卡死/损坏） | a) 超量程：超出传感器 datasheet 量程即异常；b) 恒值：连续 **T_hold=5min** 变化量 < 分辨率判卡死；c) 跳变：单周期变化 > 量程的 **10%** 判异常突变 | 量程依据 datasheet；T_hold 与跳变阈值由预实验在正常环境数据上的最大静止时长/最大正常斜率统计得出（×安全系数），论文中给出统计过程 |
| ③ 通信质量统计 | 通信中断（断线/持续丢包） | 滑动窗口 **N=20** 帧，丢包率 > **30%** 判通信故障；连续 **3** 帧无响应立即判总线异常 | 轮询帧配对统计；阈值由正常时段实测丢包率基线（预期 ≈0%）+ 容许偶发误帧定，预实验标定 |

> 论文中每个阈值必须给出：初始值 → 标定数据/方法 → 最终值 → 对误报/漏报的影响（可用参数敏感性小实验支撑）。

## 4. 实验设计

### 4.1 故障注入（≥2 类，每类 ≥10 次，推荐做 3 类）

| 类型 | 注入方法 | 对应判据 |
|---|---|---|
| A. 传感器异常 | 拔掉传感器接线 | ② 数据合理性 |
| B. 节点失联 | 节点断电 | ① 心跳超时 |
| C. 通信中断 | 拔 RS485 A/B 线 | ③ 通信质量 |

### 4.2 注入时间点与触发时刻的记录方法

- 上位机统一使用**毫秒级时间戳日志**（PC 时钟，单机单钟，无跨钟对齐问题）。
- 每次注入由实验者在上位机敲击标记键（或脚本自动断电），立即写入 `INJECT,<type>,<seq>,<t_ms>` 日志行。
- 判据触发时刻由系统自身产生 `ALARM,<rule>,<node>,<t_ms>` 日志行。
- **故障检测时间 = t_alarm − t_inject**，逐次记录，汇总均值/最大值。
- 漏报 = 注入后判据在观察窗（如 30s）内未触发；误报 = 无注入时段出现的 ALARM 条数 / 观察总时长。

### 4.3 每次注入的统计字段

`注入序号, 类型, 注入时刻, 触发时刻, 检测时间(ms), 是否误报, 是否漏报, 备注（接线异常等）`

### 4.4 常规性能测试

- 通信时延：上位机发请求→收到响应的 RTT，每节点 ≥100 次采样，报均值/最大值/P95。
- 丢包率：轮询帧丢失统计，正常时段与注入时段分开统计。
- 任务响应时间：采集任务周期触发到完成的时间（GPIO 翻转/定时器打点），报均值与最大抖动。

## 5. 采购清单（第一阶段）

| 物品 | 数量 | 说明 |
|---|---|---|
| STM32 开发板（如 F103C8T6 最小系统板，或资源更充裕的 F103ZGT6/F4 系列） | **6 块** | 3 节点 + 1 汇聚 + **备份一套**（导师明确建议备份） |
| MAX485 TTL-RS485 模块 | 6 块 | 每节点 1 + 备份 |
| USB-RS485 适配器 | 2 个 | PC 作主机，1 备份 |
| 传感器：温湿度（DHT22/SHT30）×2、光照（BH1750）、ADC 类（MQ-2 或电位器模拟） | 各 ≥4 | ADC 类便于注入"读数卡死/跳变"软件故障 |
| 杜邦线、面包板、接线端子 | 若干 | 接触不稳是最大实验风险，接线端子优于杜邦线 |
| ST-Link 调试器 | 2 个 | 烧录调试 |

> 总预算约 200~300 元。**采购前把本清单与导师过一遍**（导师可能有组内现有硬件）。

## 7. 主要风险与降级

| 风险 | 降级方案 |
|---|---|
| 硬件采购延迟 | 用 ADC 电位器模拟传感器 + 两块板先跑通最小链路；判据逻辑可在单板+模拟故障下先行标定 |
| 接触不良污染误报统计 | 接线端子固定；每次实验前跑"线路自检"；异常记录单列"接触不良"标签，不计入注入故障 |
| 时间不足 | 保底：3 类判据中先完整做 2 类 + 2 类故障注入（满足最低要求），通信中断一类若与心跳重叠可合并论证 |
